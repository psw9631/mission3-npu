# 미션 3 · Mini NPU Simulator

Cross와 X 패턴의 유사도를 **MAC(Multiply–Accumulate)** 연산으로 계산하는 Python 콘솔 프로그램입니다. 3×3 배열을 직접 입력하거나 `data.json`의 패턴을 일괄 분석할 수 있습니다.

## 실행 방법

`main.py`와 `data.json`을 같은 폴더에 두고, 해당 폴더에서 실행합니다. 과제 기준은 Python 3.8 이상이며, 실행 결과는 Fedora의 Python 3.15.0에서 확인했습니다. `json`과 `time`은 Python 표준 라이브러리입니다.

```bash
python3 main.py
```

| 파일 | 역할 |
|---|---|
| `main.py` | 콘솔 메뉴, MAC 연산, 판정, 성능 측정 |
| `data.json` | 크기별 필터와 검증용 패턴 및 기대값 |
| `README.md` | 실행 안내와 결과 리포트 |

### 메뉴 1 · 사용자 입력 (3×3)

필터 입력 방식에서 `1`을 선택하면 필터 A, 필터 B, 입력 패턴 순서로 입력합니다. 각 배열은 세 줄이며, 한 줄에 숫자 세 개를 공백으로 구분합니다. 숫자 개수가 다르거나 숫자로 변환할 수 없는 값이 있으면 같은 행을 다시 입력합니다.

| 배열 | 첫째 줄 | 둘째 줄 | 셋째 줄 |
|---|---|---|---|
| 필터 A (Cross) | `0 1 0` | `1 1 1` | `0 1 0` |
| 필터 B (X) | `1 0 1` | `0 1 0` | `1 0 1` |
| 입력 패턴 | `0 1 0` | `1 1 1` | `0 1 0` |

필터 입력 방식에서 `2`를 선택하면 위의 A와 B가 자동으로 생성되므로 입력 패턴 세 줄만 입력합니다. 두 방식 모두 이 예제에서 **A 점수 5.0, B 점수 1.0, 판정 A**가 나옵니다. 시간은 A·B를 한 번씩 채점하는 과정을 10회 반복한 평균입니다. 이어서 생성된 3×3 배열로 2차원·1차원 MAC 성능 표를 출력합니다.

### 메뉴 2 · JSON 분석

메뉴에서 `2`를 선택하면 5×5, 13×13, 25×25 패턴을 분석합니다. 예를 들어 `patterns["size_13_2"]`의 `input`을 `filters["size_13"]` 아래의 `cross` 및 `x` 배열과 비교합니다. 패턴별 점수, 판정, 기대값, 통과 여부를 출력한 뒤 성능 표와 전체 요약을 표시합니다.

### 메뉴 3 · Cross·X 패턴 생성

3 이상의 홀수 `N`을 입력하면 `N×N` Cross와 X 배열을 한 행씩 출력합니다. 예를 들어 `5`를 입력하면 두 5×5 패턴이 출력됩니다. 메뉴 1의 자동 필터와 성능 측정도 같은 생성 함수를 사용합니다.

## 구현 요약

- **MAC** · 중첩 반복문으로 패턴과 필터의 같은 위치에 있는 값을 곱해 누적합니다.
- **라벨 정규화** · 필터 키 `cross`와 `x`는 각각 `Cross`와 `X`로 변환해 내부 필터 키로 사용합니다. 기대값 `+`와 `x`도 각각 `Cross`와 `X`로 바꿔 비교합니다.
- **동점 처리** · 두 MAC 점수 차이의 절댓값이 `1e-9` 미만이면 사용자 입력 모드에서는 `판정 불가`, JSON 모드에서는 `UNDECIDED`로 출력합니다.
- **입력 검증** · JSON 파일을 읽을 수 없거나 최상위 구조가 잘못되면 안내 후 분석을 종료합니다. 개별 패턴의 키, 필터 누락, 배열 크기, 숫자 자료형, 기대값에 문제가 있으면 해당 케이스를 `FAIL`로 기록하고 다음 패턴으로 넘어갑니다.
- **패턴 생성기 보너스** · `generate_pattern(N, shape)`에 크기와 모양을 전달하면 가운데 행·열로 Cross를, 두 대각선으로 X를 만듭니다. 메뉴 1은 3×3 필터를 생성하고, 메뉴 2의 성능 측정은 3·5·13·25를 사용합니다. 메뉴 3에서는 크기를 직접 지정합니다.
- **1차원 MAC 보너스** · `flatten_matrix()`가 각 행의 값을 순서대로 이어 붙입니다. `mac_1d()`는 펼친 두 배열의 같은 인덱스끼리 곱해 누적합니다.

## 결과 리포트

기본 `data.json` 분석 결과는 **총 6건, 통과 3건, 실패 3건**입니다.

| 케이스 | Cross 점수 | X 점수 | 기대값 | 실제 판정 | 결과 |
|---|---:|---:|---|---|---|
| `size_5_1` | 0.9 | 0.8999999999999999 | X | UNDECIDED | FAIL |
| `size_5_2` | 8.9 | 0.1 | Cross | Cross | PASS |
| `size_13_1` | 0.3 | 14.700000000000008 | X | X | PASS |
| `size_13_2` | 7.499999999999997 | 7.5 | Cross | UNDECIDED | FAIL |
| `size_25_1` | 4.9 | 4.899999999999999 | X | UNDECIDED | FAIL |
| `size_25_2` | 52.9 | 0.1 | Cross | Cross | PASS |

### 실패 원인

1. `size_5_1`은 두 점수 차이가 허용오차보다 작아서 동점으로 처리됐습니다. 기대값은 X였습니다.
2. `size_13_2`는 X 점수가 약 3×10⁻¹⁵만큼 높지만 허용오차 안에 있습니다. 기대값은 Cross였습니다.
3. `size_25_1`은 Cross 점수가 약 9×10⁻¹⁶만큼 높지만 허용오차 안에 있습니다. 기대값은 X였습니다.
4. 세 케이스의 기대값은 모두 표준 라벨로 변환됐습니다. 실패가 발생한 지점은 기대값과 `UNDECIDED`를 비교하는 단계입니다.
5. 크기 검증 실습에서 `size_5_1`의 마지막 행을 빼자 해당 케이스만 크기 오류로 처리됐습니다.
6. JSON 복사본의 `size_5_2` 첫 칸을 문자열로 바꾸자 이 케이스가 숫자 자료형 오류로 실패했고, 전체 6건의 집계는 통과 2건, 실패 4건이었습니다.

### 성능 측정 및 시간 복잡도

| 크기 | 2차원 MAC 평균 (ms) | 1차원 MAC 평균 (ms) | MAC 1회 연산 수 (N²) |
|---|---:|---:|---:|
| 3×3 | 0.001090 | 0.000712 | 9 |
| 5×5 | 0.001753 | 0.001159 | 25 |
| 13×13 | 0.010001 | 0.006719 | 169 |
| 25×25 | 0.029843 | 0.022957 | 625 |

7. 크기마다 같은 X 패턴과 Cross 필터를 2차원·1차원 방식에 사용했습니다. `perf_counter()`로 각 MAC을 10회 반복하는 구간의 총 시간을 재고 호출 1회당 평균을 구했습니다.
8. 배열 생성과 1차원 변환, JSON 읽기, 화면 출력은 측정 구간 밖에서 수행했습니다.
9. 2차원 MAC은 N개 행에서 각각 N개 열을 방문하므로 곱셈과 누적을 N²회 수행합니다. 시간 복잡도는 O(N²)입니다.
10. 1차원 MAC도 길이가 N²인 리스트 전체를 순회하므로 시간 복잡도는 O(N²)입니다. 배열을 펼치는 데도 O(N²) 시간이 들고, 펼친 배열에는 O(N²) 공간이 필요합니다.
11. 5×5에서 25×25로 한 변이 5배 길어지면 연산 위치는 25개에서 625개로 25배 늘어납니다. 이번 측정에서도 크기가 커질수록 두 방식의 평균 시간이 증가했습니다.
12. 이번 실행에서 두 방식의 점수는 모든 크기에서 같았습니다. 25×25의 1차원 MAC은 약 23% 짧게 측정됐으며, 표의 시간은 한 번의 실행에서 얻은 값입니다. 반복문과 함수 호출의 고정 비용도 포함되므로 시간 비율이 연산 횟수 비율과 정확히 일치하지는 않습니다.
